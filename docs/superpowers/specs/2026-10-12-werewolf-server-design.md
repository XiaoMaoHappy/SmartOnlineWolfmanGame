# 在线狼人杀平台服务端 — 设计文档

日期：2026-10-12
状态：已批准

## 1. 概述

基于 Python Flask 的在线狼人杀平台服务端。支持 6-12 人房间、基础狼人杀规则、
REST API + 浏览器轮询的交互方式，附带可直接用浏览器打开的简易网页前端。

## 2. 技术选型

- 服务端：Flask（纯 HTTP JSON REST API）
- 通信：浏览器前端每 2 秒轮询 `/state` 获取最新状态
- 存储：服务器内存 + JSON 文件持久化（`werewolf_rooms.json`），服务重启后恢复未结束房间
- 并发：`threading.Lock` 保护房间状态；单人房间锁 + 全局锁
- 鉴权：每个玩家加入房间时由服务端签发唯一 `token`，所有行动接口凭 token 校验身份
- 前端：单个 `static/index.html`，原生 HTML/JS，无构建、无依赖

## 5. 角色技能规则

### 5.1 狼人（普通）
- 夜晚与所有狼人阵营共同选择一名玩家击杀，狼队统一目标。

### 5.2 狼美人
- 夜晚与狼人一起杀人（目标统一）。
- 被动【殉情】：**仅在被投票放逐时**，可选择魅惑一名存活玩家，二者一同出局。
- 被狼刀误杀、被女巫毒死等夜晚死亡时不可魅惑。

### 5.3 预言家
- 每晚查验一名存活玩家，得知其为「狼人」或「好人」。

### 5.4 女巫
- 一瓶解药（可救当晚被刀者，含自救）、一瓶毒药（毒杀任意玩家）。
- 同一晚救、毒不可同时使用；每瓶药全场仅一次。

### 5.5 猎人
- 被狼刀、被投票放逐时**可**开枪带走一名存活玩家。
- 被女巫毒死、被狼美人魅惑带走时**不可**开枪。

### 5.6 守卫
- 每晚守护一名存活玩家，被守护者当晚不会被狼刀。
- 守护抵消狼刀，但挡不住毒药与魅惑。

## 6. 游戏流程状态机

```
waiting ──开始(≥6人)──> night ──所有行动完成/强制结算──> day ──投票结算──> night 或 ended
ended（胜负已分）
```

### 6.1 night 阶段
1. 面向全部存活玩家、按角色受理行动：
   - 守卫：`guard`（免受狼刀）
   - 狼人阵营（含狼美人）：`kill`（选刀目标，全队统一，后提交者覆盖）
   - 预言家：`verify`（验人，可记入 `verify_history`）
   - 女巫：`save`（用解药）/ `poison`（用毒药），每瓶限一次
   - 无技能角色自动标记为已完成
2. 全部有行动能力的角色提交完毕后自动结算；房主可调用 `resolve_night` 强制结算。
3. 结算逻辑：
   - 狼刀目标被守卫守护 → 免死
   - 女巫当晚用解药 → 被刀者免死（守卫先判定，救活仅当未被守且被刀）
   - 毒药目标出局
   - 产出 `night_deaths`，进入 day。

### 6.2 day 阶段
1. 公布 `night_deaths`（死讯）。
2. 讨论（发言板 `chat`，不限时间，不删人）。
3. 全体存活玩家投票 `vote`，不投票可弃权。
4. 结算：
   - 得票最高者被放逐；平票则无人出局（平安日）。
   - 放逐者为狼美人 → 进入魅惑结算：狼美人选 `charm` 目标（或跳过/不选），目标随同出局。
   - 放逐者为猎人 → 进入开枪结算：猎人选 `gun` 目标（或跳过/不开枪）。
   - 猎物人/被毒或被魅惑带走者不可开枪。
5. 出局结算完成后判断胜负。

## 7. 胜负判定

- 狼人阵营存活数为 0 → 好人胜利。
- 场上狼人阵营存活数 ≥ 存活好人数 → 狼人胜利。
- 存活神职为 0 或存活平民为 0 → 狼人胜利。
- 其余情况游戏继续。

## 8. REST API

统一响应：`{"code": 0, "data": ..., "msg": "ok"}`；错误 `code != 0`。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/rooms` | 创建房间 `{name, ai_count?}` → `{room_id, player_id, token}` |
| POST | `/api/rooms/<id>/join` | 加入房间 `{name}` → `{player_id, token}` |
| POST | `/api/rooms/<id>/start` | 房主开始游戏（≥6 人） |
| POST | `/api/rooms/<id>/restart` | 房主在结束后重开一局（回到大厅，保留玩家与 AI 配置） |
| GET  | `/api/rooms/<id>/state` | 轮询状态（携带 token，返回个人视角） |
| POST | `/api/rooms/<id>/action` | 行动 `{token, type, target?}`（guard/kill/verify/save/poison/vote/charm/gun/pass） |
| POST | `/api/rooms/<id>/resolve_night` | 房主强制结束夜晚（超时兜底） |
| POST | `/api/rooms/<id>/resolve_day` | 房主强制结束投票 |
| POST | `/api/rooms/<id>/chat` | 发言板发言 `{token, message}` |
| GET  | `/` | 返回 `static/index.html` 前端 |

### 8.1 /state 个人视角
- 公开信息：房间号、状态、回合数、玩家名单及存活/死亡/出局方式/是否 AI、死讯、日票情况、发言板。
- 私密信息：自己的身份；狼人视角见狼队友；预言家可见历史验人结果。
- 不返回他人身份、不返回他人夜晚行动。

## 9. AI 玩家接入

- 创建房间时房主可通过 `ai_count` 指定 1~11 名 AI 玩家，AI 自动入局，玩家名单带 `is_ai` 标记。
- 服务端 `bot.py` 在**每个状态变化点**（开局、提交行动、强制结算）后台线程驱动需要行动的 AI：
  1. 构造中文提示词（身份说明/规则简表/当前局势/场上发言/可用行动与可选目标/严格 JSON 输出要求）；
  2. 调用约定的 `ai_generator(prompt) -> str` 获取决策 JSON 并执行；
  3. 模型缺失/异常/回复非法时退回内置启发式策略（尽力推进对局不卡死）。
- `ai.py` 同目录提供 `ai_generator(prompt)` 即被自动发现，无需改代码。
- 全部存活玩家行动完成后按引擎自动结算，AI 与真人流程完全一致。

## 10. 错误处理

- token 缺失/非法 → 401
- 非房主操作/违规行动（越权、目标非法、时机不对）→ 403
- 房间不存在 → 404
- 参数校验失败 → 400
- 服务端错误统一 500 且不泄露堆栈。

## 10. 测试

`tests/test_game.py` 使用 pytest 直接测试 `game.py` 引擎（无 Flask 依赖）：

- 各人数发牌数量与身份分布正确
- 守卫挡刀 / 女巫救与毒 / 救毒不可同晚
- 夜晚死亡结算（多人死亡、狼人自刀）
- 白天投票：平票平安日、狼美人放逐魅惑、猎人放逐开枪、毒死猎人不开枪
- 胜负判定：狼人全灭（好胜）、狼人数量反超（狼胜）、神/民全灭（狼胜）
- 全流程冒烟：6 人局完整打一局到分出胜负
- API：创建/加入/开局/权限/鉴权/隐私/落盘恢复
- AI：提示词构造、LLM 决策提交、非法回复兜底、无模型启发式推进、AI 参与猎人开枪子阶段
- 重开一局：结束后保留玩家与 AI 配置重置对局
